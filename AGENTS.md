# Project continuity

For revision work, read `docs/HANDOFF.md` first, then `docs/revision-audit.md` and the relevant checklist under `docs/superpowers/plans/`. They record completed work, deployed commits, verification evidence, and known limits across this project and its sibling.

These are dated records. Recheck current source/git/deployment state and any updated requirements before making new completion claims. Read screenshot annotations as well as document text, and verify affected complete user flows rather than only helper functions.

## Keep continuity records current

For every future implementation, fix, revision review, or deployment, update `docs/HANDOFF.md`, `docs/revision-audit.md`, and any affected checklist before handing the task back. Record what changed, what is complete versus pending or blocked, verification results, relevant commits, and deployment status. If work is unfinished, leave concrete next steps; never mark unverified work complete.

Commit and push these documentation updates alongside the work when pushing is authorized. When an update changes the shared cross-project status, synchronize the relevant summary in the sibling repository's handoff as well. These instructions refer to repository documentation; they do not authorize editing the professor's source Google Doc.
